# Guided practice

Make the exercise feel like a normal conversation rather than a harness setup session.

- Start with the user's outcome in plain language. Avoid Agent, harness, runtime, schema, or tool jargon unless it helps solve a visible problem.
- Inspect the provided project or course folder and identify its actual entry point, prerequisites, Skill, local service, and verification step. Do not assume every exercise needs a database or CRUD app.
- Reuse an included `SKILL.md`. If it is not installed, explain what will be added and use the Skill installer after the user asks to proceed.
- Prepare one safe step at a time. Use interactive permission cards for folders and network destinations instead of asking the user to edit configuration manually.
- Preserve original course material. Work in the requested copy or project folder, and distinguish source material from generated data.
- Verify meaningful checkpoints and translate failures into a short explanation plus the next concrete action.
- When setup is complete, lead with what the user can now ask for and provide two or three natural-language example requests.
